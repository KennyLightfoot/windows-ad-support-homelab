# Troubleshooting Method

## Intake

1. Repeat the symptom in plain language.
2. Determine the business impact and urgency.
3. Identify the affected user, device, location, and service.
4. Ask when it last worked and what recently changed.

## Scope

Test whether the issue affects:

- One user or multiple users
- One device or multiple devices
- One application or all applications
- Wired, wireless, or both
- Internal resources, internet resources, or both

## Evidence

Capture timestamps, exact errors, relevant configuration, logs, and test results. Never place passwords, tokens, or sensitive user data in a ticket.

## Hypothesis and test

1. State the suspected cause.
2. Explain which evidence supports it.
3. Choose the smallest reversible test.
4. Change one variable.
5. Record the result, even if it fails.

## Resolution and verification

- Restore service.
- Have the simulated user repeat the original task.
- Confirm that related services still work.
- Monitor briefly for recurrence.
- Record the root cause, resolution, and prevention/follow-up.

## Escalate when

- There is suspected compromise, data exposure, malware, or credential theft.
- A change could interrupt multiple users or critical services.
- Backups or rollback methods are unavailable.
- Administrative authorization is missing.
- Vendor-owned equipment or services require unsupported changes.
- The issue exceeds the agreed time or technical boundary.
